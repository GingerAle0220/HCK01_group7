# ver.3 仕様書

## 設計方針

このリポジトリは Processing による演奏制御 UI と，別ウィンドウで動くクマアニメーションを組み合わせたスケッチです．まず UI 側で演奏条件を確定し，シリアル通信で Master Arduino に送信します．その後は Master 側からの開始・終了通知に合わせて UI をロックし，BearWindow 側のゲーム演出と状態同期を行います．

README では，次の順序で仕様を整理します．

1. プロジェクト全体の目的を定義する．
2. UI.pde と BearWindow.pde の責務を分けて説明する．
3. 実行に必要な環境，コマンド，ディレクトリを明示する．
4. 開発時に詰まりやすい箇所を先に潰す．

## プロジェクトの概要

本プロジェクトは，ハッカソン向けの演奏制御システムです．メイン画面では BPM，演奏順，共通オクターブを設定し，初回送信パケットを Master Arduino に送ります．BearWindow ではクマのランゲーム風アニメーションを表示し，BPM に応じてスクロール速度や演出を変化させます．

UI 側の特徴は次の通りです．

- BPM は 30 から 180 の範囲で設定でき，演奏中でも変更できます．
- 楽器の演奏順は 1 から 3 のキーで指定し，演奏中は変更できません．
- 共通オクターブは -1 から 9 の範囲で指定し，送信時は 2 桁の数値に変換されます．
- 送信は初回に 8 バイト固定パケットを送り，以後は BPM 更新を想定した 3 桁パケットを送ります．
- Master から START, PLAYING, FINISH, STOP を受け取ると UI のロック状態が切り替わります．

BearWindow 側の特徴は次の通りです．

- 別ウィンドウとして起動し，Processing の P2D レンダラーで描画します．
- BPM に応じて背景，雲，木，コイン，障害物，クマの移動速度が変わります．
- ジャンプ，コイン収集，障害物回避，スコア表示，ランキング表示を持ちます．
- 画像リソースはメインスケッチ側で読み込み，BearWindow へ受け渡します．

## 使用している主な技術

- Processing
- Processing Serial ライブラリ
- Java ベースの .pde スケッチ構成
- 別ウィンドウ起動の PApplet.runSketch
- 画像アセットを使った 2D ドット絵描画
- キーボード入力とマウス入力による UI 操作

## 主要仕様

### UI.pde

UI.pde はメイン画面の制御を担当します．役割は次の通りです．

- シリアル通信の初期化と送信処理
- BPM，演奏順，共通オクターブの状態管理
- 送信ボタン，リセットボタン，オクターブ増減ボタンの描画と操作
- Master からのシリアル受信によるロック制御
- BearWindow への BPM と再生状態の同期
- 送信パケットの生成とログ出力

画面上の操作仕様は次の通りです．

- 上下キーで BPM を 10 ずつ変更する．
- 1 から 3 のキーで楽器の演奏順を設定する．
- 送信ボタンで初回パケットを送る．
- リセットボタンで演奏順を初期化する．
- オクターブの上下ボタンで共通オクターブを変更する．
- スペースキーで BearWindow 側のジャンプを発火する．

### BearWindow.pde

BearWindow.pde は別ウィンドウの演出とゲーム進行を担当します．役割は次の通りです．

- 背景，地面，雲，木，石，コインの描画
- クマの歩行，ジャンプ，ダメージ状態の切り替え
- コイン収集と障害物接触の判定
- スコア，ベストスコア，ランキングの更新
- BPM に連動したスクロール速度の制御
- 演奏中と終了後の UI 表示

## 必要な環境変数やコマンド一覧

### 環境変数

このプロジェクトの実行に必須の環境変数はありません．

ただし，次の点は実機接続時に確認が必要です．

- シリアルポート名は UI.pde 内の portName に直接書かれています．
- 実機のポートに合わせて portName を変更してください．
- シリアル未接続時はシミュレーションモードで起動します．

### コマンドと操作

通常は Processing IDE から実行します．

    1. Processing IDE で ver.3/UI を開く．
    2. 実行ボタンでスケッチを起動する．
    3. 必要に応じて Master Arduino 側のスケッチを書き込む．

補助的に使う操作は次の通りです．

- 実機接続時は UI.pde の portName を修正する．
- シミュレーション時はシリアル接続なしでそのまま実行する．
- シミュレーション中に演奏終了を疑似発火したい場合は s キーを使う．

## 開発環境の構築方法

1. Processing をインストールする．
2. ver.3/UI を Processing で開く．
3. data フォルダ内の画像が欠けていないか確認する．
4. 必要なら UI.pde のシリアルポートを実機に合わせて修正する．
5. 実行ボタンでスケッチを起動する．
6. 実機連携を行う場合は，Master Arduino 側のシリアル仕様と START, FINISH の通知を合わせる．

### 開発時の確認ポイント

- メインスケッチ側で画像を loadImage してから BearWindow に渡す．
- BearWindow 内で直接 loadImage しない．
- 実機とつながらない場合はシミュレーションモードで動作確認する．
- シリアル通信中は UI の一部がロックされる仕様を前提にする．

## トラブルシューティング

### 画像が表示されない

- data フォルダに画像があるか確認する．
- 画像名の大文字小文字が一致しているか確認する．
- BearWindow 側で直接画像を読み込まず，UI.pde 側から渡しているか確認する．

### シリアルポートが見つからない

- UI.pde の portName が実機のポートと一致しているか確認する．
- Arduino IDE など他のアプリがポートを占有していないか確認する．
- 実機が不要ならシミュレーションモードで起動する．

### UI がロックされたまま戻らない

- Master Arduino 側から FINISH もしくは STOP が送られているか確認する．
- シミュレーション時は s キーで終了処理を代替できる．
- シリアル受信ログが出ているか確認する．

### BearWindow が開かない，または描画が不安定

- Processing のバージョンを確認する．
- OpenGL 系の問題がある場合は BearWindow.pde の size 指定を P2D なしに戻して試す．
- 実行環境の GPU 設定や Java 環境に問題がないか確認する．

### 演奏順が設定できない

- 演奏中は演奏順とオクターブがロックされる仕様になっている．
- 送信前の待機状態で設定を行う．
- リセットボタンで順番を初期化してから設定し直す．
