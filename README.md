## 1. システム概要 ＆ 機材構成

本システムは，1台のPC（Processing）を指揮者UIとし，1台のMaster Arduino（制御ハブ）を介して，4台のSlave Arduino（各楽器）を協調制御する自律型アンサンブルシステムである．

### 1.1 各ノードの役割
* **指揮者UI (PC / Processing)**
  * ユーザーからのBPM入力，オクターブ設定，演奏順番入力を受け付ける．
  * 演奏が開始されると，演奏の協調性が保たれるようにUI操作をBPM以外自動でロックする．
  * 各Slaveから送られてくる音符データ（MIDIノート番号）を受信し，即座に周波数へ変換してPCのスピーカーから発音する．
* **Master Arduino (1台)**
  * Processingからシリアル通信で設定パケットを受け取る．
  * 受信したBPM値から「音符1つあたりの送信間隔（ミリ秒）」を計算し，演奏開始から終了まで，I2Cバスを通じて全Slaveへテンポパルス（BPM情報）を送り続ける．
* **Slave Arduino (4台)**
  * **ピアノ，フルート，木琴 (Slave 1〜3)**：演奏順番制御の対象．Masterからテンポパルスを受信するたびに，自身の楽譜配列を進め，音符データをProcessingへシリアル送信する．
  * **ドラム (Slave 4)**：演奏順番・オクターブ制御の対象外．開始合図を受け取った瞬間から，他の楽器の順番に関係なく，BPMに従って一定のリズムを自律して刻み続ける．

## 2. 最新通信パケット仕様

### 2.1 初回一括設定パケット（9バイト）
演奏ボタンを押した最初の1回だけ，ProcessingからMasterへ送信される．
* **フォーマット**: `[オクターブ:2桁]` + `[演奏順:3桁]` + `[BPM:3桁]` + `\n`
* **内訳**:
  1. **オクターブ (2桁)**: 国際式（`-1`〜`9`）の11段階を，`00`〜`10` の2桁固定文字列に変換（例: オクターブ4 ➔ `05`）．
  2. **演奏順 (3桁)**: ピアノ，フルート，木琴の演奏順番（`1`〜`3`，未設定は `0`）を並べたもの（例: `132`）．※ドラムは除外．
  3. **BPM (3桁)**: `030`〜`180` の3桁固定文字列（例: `120`）．

### 2.2 演奏中テンポパケット（4バイト）
2回目以降の演奏開始時，および演奏中にリアルタイムにBPMが変更された場合，このパケットのみを送り続けて通信負荷を下げる．
* **フォーマット**: `[BPM:3桁]` + `\n`

## 3. 演奏・発音の内部処理フロー

### 3.1 テンポ（持続時間）の動的計算ロジック
Master Arduinoは，受信したBPMから8分音符1つあたりの実時間間隔 $T$ [ms] を以下の計算式で割り出し，タイマー（`millis()`）の周期としてセットする．
$$T = \frac{60000}{\text{BPM}} \times \frac{1}{2}$$

### 3.2 発音サイクル
1. **Master** が計算した間隔 $T$ ごとに，I2Cバスへ「テンポパルス」を一斉送信する．
2. **Slave（各楽器）** はパルスを受信するたびに，内部の「パルスカウンタ」をカウントアップする．
3. 自身の演奏順番から計算された「待機パルス数」に達したら演奏状態（`isPlaying`）になり，内蔵された楽譜配列（現在のスロット）のMIDI音高データを，個別のシリアル通信で直接PC（Processing）へ送信する．
4. **Processing** は受信したMIDI信号をオクターブ設定に基づいて補正し，を用いてスピーカーから発音する．

## 4. 演奏中のUIロック制御（Processing側）

Processing側のUIは，送信ボタンを押した時点で `isPlaying = true` に切り替わり，演奏中は演奏順・オクターブ設定の変更をロックする．演奏終了後は，Master Arduinoから受信するシリアルメッセージに応じてUIロックを解除する．

### 4.1 ロック解除の動作
* **UIロック開始**:
  * 実機接続時は，`serialEvent()` で `START` または `PLAYING` のメッセージを受信したときに `isPlaying` を `true` に切り替える．
  * シリアルポートが接続されていないシミュレーションモードでは，送信ボタンのクリック時に `isPlaying` を `true` にしてロックする．
* **解除トリガ**:
  * `serialEvent()` で `FINISH` または `STOP` のメッセージを受信したとき，`isPlaying` を `false` に戻す．
* **補足**:
  * シミュレーションモードでは，`'s'` キー入力で手動解除が可能である．

## 5. 各プログラム（ファイル）の役割・内部処理概要

### 5.1 `UI/UI.pde` (指揮者UI)
* **役割**: 全体のGUI表示，キーボード（1〜3キー，↑↓キー）によるパラメータ設定，Serial通信を通じたMasterからの再生状態受信．
* **内部処理**: `draw()` でUI表示を更新し，`serialEvent()` で `START` / `PLAYING` 受信時に `isPlaying = true`，`FINISH` / `STOP` 受信時に `isPlaying = false` を切り替える．

### 5.2 `Master.ino` (同期ハブ)
* **役割**: PCからのパケット受付とパース，I2Cバス経由での全スレーブへの情報配信．
* **内部処理**: 受信パケットの文字数（8文字か3文字か）で初回設定か演奏中テンポ変更かを識別．非ブロッキングタイマーで，正確なBPM間隔のI2Cブロードキャストを維持する．

### 5.3 `Slave.ino` (楽器スレーブ：ピアノ・フルート・木琴共通)
* **役割**: 自身の楽譜データの保持，担当順番に応じた演奏開始タイミングの制御．
* **内部処理**: I2C割り込み関数内で，設定データ（`S`）かテンポパルス（`P`）かを判別．自機のアドレスから演奏順を割り出し，開始条件（例：2番手なら8パルス待機）を満たしたら，パルス毎に楽譜配列のインデックスを進めてMIDIデータをシリアル出力する．

### 5.4 `Slave_Drum.ino` (ドラム専用スレーブ)
* **役割**: 順番・オクターブに縛られない，完全独立したリズムキープ．
* **内部処理**: 初回設定パケットからBPMのみを抽出．Masterからテンポパルス（`P`）を受信した瞬間，待機時間なしで1パルス目から交互にスネアやハイハットのMIDIデータをシリアル送信し続ける．
